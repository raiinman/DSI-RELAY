# Measurement-preview hosted-runner validation

Status: the first full hosted build and contained smoke passed on [run 36287058192](https://github.com/raiinman/DSI-RELAY/actions/runs/36287058192), committed revision `20a40228e576a60cb6b0c2ae5b3bfacd72c430e4`. This is a review workflow, not a public release or a replacement for a separate standard-account test.

The first hosted run was cancelled during its build after confirming that artifacts from this public repository would be downloadable by repository readers. It uploaded no artifacts. The workflow now retains only the sanitized JSON report; the ZIP is validated on the ephemeral runner and is not uploaded. Earlier hosted runs exposed two portability defects. Windows CRLF checkout changed the reviewed `Cargo.lock` fingerprint, so root `.gitattributes` now pins it to LF. On the hosted runner, text matching against the pipe security descriptor rejected the owner and access rule; verification now checks their canonical SIDs and retains the strict current-user-only policy. Windows PowerShell 5.1 process redirection also changed CLI stdin; the benchmark now supplies a temporary UTF-8 input file and removes it after each command. The passed run verified both the assembled bundle and fresh extraction (98 hashed files), completed all seven correctness checks on two 100-file projects, checked report privacy and process/temporary-directory cleanup, and uploaded only its sanitized JSON report. No hosted run uploaded a binary.

On a push to that branch, `.github/workflows/measurement-preview.yml` checks out the committed revision on `windows-2025`, selects the stable x64 MSVC Rust toolchain, and calls the existing locked, remapped release packager. `.github/Validate-PreviewRunner.ps1` checks the zip SHA-256, verifies the assembled folder and a fresh extraction, requires the manifest to identify the pushed commit and a clean packager-built source tree, and requires the pinned third-party notice and SQLite technical checks. It runs the bundled benchmark with one run and 100 synthetic files per project. Before uploading a seven-day report artifact, it checks the report status, scans the report and extracted payload for current account/machine identifiers and token-shaped values, and confirms that the benchmark added no lasting `relayd.exe` process or owned synthetic-project directory. The uploaded artifact contains only the checked hosted-runner JSON report. The binary archive remains on the ephemeral runner and is not uploaded to the public repository.

After the existing hosted smoke uploads its report, a separate step creates a temporary local standard Windows account with a random password held only in runner memory. It copies the verified package to an owned staging directory and runs the packaged verifier and one 100-file synthetic sample through a secondary logon with a fresh machine environment, so the runner's process credentials are not forwarded. The child checks that it has the new account identity, no administrator token, a nonzero Windows session, and a loaded user registry profile. The parent checks correctness, report privacy, residual daemon and fixture cleanup, then removes the account and owned staging directory. Only the screened JSON account check and benchmark report are eligible for a separate seven-day artifact. The package, password, child process output, and raw logs are not uploaded. This new check has not yet run on the hosted image; its outcome must be inspected before citing it as evidence.

The build job has only repository read and artifact write permissions. It creates no GitHub Release, does not sign Windows code, does not change `main`, and does not clear manifest release gates. Archive attestation is deferred until a public binary distribution is approved; public-repository workflow artifacts are downloadable by repository readers.

The workflow follows the current [GitHub branch trigger and permission syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) and [artifact upload behavior](https://github.com/actions/upload-artifact). [GitHub documents](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts) that repository readers can download workflow artifacts, which is why this workflow publishes only the report.

The report artifact from that run was downloaded and checked locally; its SHA-256 is `83d3186068c23f6f5d34c923ef0f75557bf2c29986cf992ac06c6e3173caf734`. It records a 2-core/4-thread, 16 GiB hosted VM with SSD-class temporary storage, one complete sample, and 0 ms process CPU during a five-second idle observation. This synthetic result is useful CI evidence, not a minimum-tier budget.

Evidence still required: an interactive sign-in to a separate standard Windows desktop account and the full package checklist, minimum/recommended hardware-tier samples, a real creator-app session, and the remaining legal, publisher-trust, and security release review. The new hosted check exercises a different non-administrator identity and profile through secondary logon; it cannot demonstrate a normal desktop sign-in or creator-app contention. Watcher and idle behavior there remain empirical CI results, not proof for a normal user desktop with the target hardware or editor installed.
