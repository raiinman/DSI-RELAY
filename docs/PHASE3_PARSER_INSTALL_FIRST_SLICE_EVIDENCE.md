# Phase 3 local parser installation first slice

Status: offline first slice. This does not close Phase 3 or qualify a public product beta.

The local `relay parser-install <project-id> <manifest.json> <worker.exe> <extensions-comma-separated> --allow-source-delivery` path lets a user supply a generic parser package without editing `parser-installations.json`. RELAY must be stopped. The operator explicitly authorizes delivery of the named project's indexed UTF-8 source files for the selected extensions, subject to the daemon's existing 1 MiB limit and idle/ready guards. Starting RELAY activates the staged grant; the configured project adapter ID/version must still match. One project can have one grant in this slice.

The installer requires adjacent ordinary `manifest.json` and `.exe` files, a manifest at most 1 MiB, a worker at most 128 MiB, a valid adapter protocol/command binding, a matching artifact and worker-component SHA-256, and a manifest requesting exactly the named project's read scope. Network, project writes, credentials, subprocesses, and external apps are rejected. It copies both files into a new dedicated RELAY package directory, revalidates the copied package, then atomically publishes the version-1 grant. A process-held lock serializes concurrent installers and is released after a crash. Existing grant files are preserved and appended, up to 32 projects; a duplicate project fails. The daemon independently revalidates the grant and artifact at every start.

This is an offline maintenance path because the current daemon owns an immutable parser runtime loaded at startup. It does not offer live installation, update/removal, a package catalog, publisher signature/reputation verification, or complete installation lifecycle through the shared command registry. The CLI rejects a present `host.json`, including a stale one; a crashed host's stale marker needs existing local recovery before installation. A simultaneous host launch may observe the previous grant generation and require another restart. The package format in this slice is one executable plus its manifest, so packages with extra runtime files are unsupported. Before product beta, put install/update/removal behind a host command with shared authorization and observable transaction state, and test crash/recovery plus the real tool adapter.

Verification: focused `relay` library tests cover a valid staged grant, exact copied bytes and digest, a second project appended without changing the first grant, duplicate rejection, explicit source-delivery opt-in, over-permission rejection, digest mismatch, and running-host rejection. The live daemon parser-dispatch suite also stages a synthetic fixture through the installer, starts the daemon, binds and indexes the project, and observes a parser-produced dependency edge and healthy installation status. No released preview artifact is rebuilt from this branch.
