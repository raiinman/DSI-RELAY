# Measurement-preview hosted-runner validation

Status: workflow added for `phase3/project-discovery`; no GitHub run has passed yet. This is a review workflow, not a public release or a replacement for a separate standard-account test.

On a push to that branch, `.github/workflows/measurement-preview.yml` checks out the committed revision on `windows-2025`, selects the stable x64 MSVC Rust toolchain, and calls the existing locked, remapped release packager. `.github/Validate-PreviewRunner.ps1` checks the zip SHA-256, verifies the assembled folder and a fresh extraction, requires the manifest to identify the pushed commit and a clean packager-built source tree, and requires the pinned third-party notice and SQLite technical checks. It runs the bundled benchmark with one run and 100 synthetic files per project. Before uploading a seven-day review artifact, it checks the report status, scans the report and extracted payload for current account/machine identifiers and token-shaped values, and confirms that the benchmark added no lasting `relayd.exe` process or owned synthetic-project directory. The uploaded artifact contains the review-only zip, its checksum, and the checked hosted-runner JSON report.

The build job has only repository read and artifact write permissions. A separate job attempts an archive attestation only when the repository is public; that job has its own OIDC and attestation permissions and rechecks the downloaded zip checksum. Neither job creates a GitHub Release, signs Windows code, changes `main`, uploads tester project content, or clears manifest release gates.

The workflow follows the current [GitHub branch trigger and permission syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax), [artifact upload behavior](https://github.com/actions/upload-artifact), and [artifact attestation requirements](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations). Attestations depend on repository plan and visibility; the conditional job conservatively runs only for a public repository.

Evidence still required: a successful actual GitHub run, downloaded-artifact verification, separate standard Windows account, minimum/recommended hardware-tier samples, a real creator-app session, and the remaining legal, publisher-trust, and security release review. A GitHub-hosted runner is a fresh CI environment and may be non-interactive. Watcher and idle behavior there is only an empirical CI result, not proof for a normal user desktop with the target hardware or editor installed.
