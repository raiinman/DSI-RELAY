# Phase 3 installed parser dispatch evidence

Status: PASS for one synthetic installed parser and two live projects, 2026-09-26. Hardware-tier parser cost and public installation UX remain open.

## Contract

The per-user daemon reads a version-1 `parser-installations.json` from its local state directory at startup. Each installation explicitly selects one project, canonical manifest and worker paths, exact adapter ID/version, worker SHA-256, target tool/version, allowed source extensions, and `allow_source_delivery: true`. A missing file enables no parser. A malformed or mismatched grant grants no parser access and appears as degraded parser health through the canonical status/doctor commands. The manifest must request exactly that project's read scope and bind `adapter.dependencies.parse`; network, write, credential, subprocess, and external-app permissions are rejected. The existing broker revalidates the installed worker artifact and invokes it through the qualified Windows sandbox. Project configuration still declares a preference only; automatic dispatch requires an exact match to the installed grant.

The daemon processes at most one selected source per second after signed-in-session input inactivity and while no foreground RELAY write is active. The production idle threshold is 30 seconds; the debug fixture accelerates it. A cheap ready-generation/configuration query avoids cloning indexed file inventories every idle poll. The full project file list is fetched only when its ready generation or configuration revision changes. Only matching extensions and UTF-8 files at most 1 MiB are delivered. The daemon hashes the exact bytes before sandbox delivery, requires the digest to match the indexed source, and checks a bounded fresh read after parsing. Canonical paths must remain inside the project root; the mailbox carries project-relative source identity and content, not the absolute root.

The parser observation stays untrusted. Immediately before sending source bytes, Core rechecks the ready generation, current configuration selection, and indexed source digest. The daemon submits the observation through `project.dependencies.replace` with the current index generation, source digest, parser producer identity, and an additive configuration-selection guard. Core verifies ready index state, source and target membership, and the exact current configuration revision/adapter ID/version in the same storage transaction as edge replacement. Updating project configuration invalidates derived edges. Changed source or target paths trigger reparse; an oversized delta or rebuild resets the in-memory parser cache conservatively. Deleting a target invalidates its edge and a later restoration permits reparse.

## Verification

- The live `phase3_parser_dispatch` fixture installed a digest-pinned synthetic package for Alpha, then imported and indexed Alpha and Bravo with overlapping relative files and the same declared adapter. Alpha automatically gained one edge through the sandbox; Bravo, without a project grant, remained empty.
- Editing Alpha's source and reconciling replaced the edge. Deleting its target and reconciling removed the edge; restoring the target and reconciling restored it. A configuration version change cleared the edge, and a stale guarded parser replacement failed with `PROJECT_CONFIG_CONFLICT`.
- The original second fixture changed the grant's worker digest and confirmed daemon readiness failed. Parser-health work superseded that fail-stop host behavior with a degraded, operator-visible status that still denies source delivery; see the tenth-slice evidence. The original two live tests passed. `cargo test -p relay-core --lib` passed 45 tests; `cargo test -p relay-contracts --lib` passed 9 tests; `cargo check -p relayd` passed. The adapter fixture binary was built before the targeted live run.

## Limits

Installation is currently an explicit local state-file operation loaded at daemon startup; there is no CLI/dashboard installation command or package catalog. A project binding by itself never installs or authorizes a parser. Source extension selection is part of the local grant rather than a generic Core rule. Parser failures leave the source without a new edge and retry after a short delay. Operator-visible health and bounded diagnostic events were added in the tenth slice. Successful parse observations are cached in daemon memory, so daemon restart conservatively reparses matching sources at a rate of at most one per second after the idle gate. This can take substantial time for a large project and has not been measured on minimum/recommended hardware. Binary or oversized sources are skipped. Synthetic dispatch proof does not establish compatibility with a real editor/toolchain adapter or a supported-tier resource budget.
