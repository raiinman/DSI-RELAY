# Phase 4 compact result context first slice

Status: bounded foundation on the active development branch; Phase 4 is not closed.

`result.context` accepts a durable result ID and a requested result-body budget of 512–16,384 serialized JSON bytes. It also accepts an optional `required_pointers` array of 1–8 unique JSON Pointers, each at most 256 characters and 256 UTF-8 bytes. Core applies the same project authority check as `result.get`. It returns the result ID, payload digest and byte count, source trust label, exact selected scalar facts with JSON Pointer locations, an omitted-scalar count, a truncation flag, and the `result.get` command name for full evidence. No fact value is shortened to fit. The response body is measured after JSON serialization and must fit the requested budget; the outer command response envelope is separate.

The current deterministic selection favors short identifier, error-code, and version tokens, then named numeric counts, byte sizes, times, generations, and revisions, then status fields. Required pointers move matching eligible facts ahead of that default order. A missing or ineligible pointer fails with a generic `CONTEXT_FACT_UNAVAILABLE`; an all-required view that exceeds the budget fails with `CONTEXT_BUDGET_TOO_SMALL`. The output never silently omits a required fact. Requests without `required_pointers` retain the previous byte-for-byte selection in the Gauntlet. The selector still rejects path-like and secret-related keys, unsafe object-key segments, path-like identifier values, and narrative strings. This is conservative local presentation filtering, **not** classification or permission to send the result to a remote model. The full source payload remains available through authorized `result.get`.

Contract effect: `required_pointers` is an additive optional argument on `result.context@1`; the result schema is unchanged. The shared validator now supports `minItems`, `maxItems`, `uniqueItems`, and `maxLength` to bound the array, while Core checks JSON Pointer escape syntax and UTF-8 byte length. Invalid input returns `VALIDATION_FAILED` without echoing pointer values. Existing callers can omit the field and keep the same command version.

Verification: `cargo test -p relay-contracts -p relay-core --locked` passed 10 contract tests, 51 Core unit tests, and the Gauntlet integration test. Tests compare a 768-byte compact view with a full payload more than three times larger, verify exact identifier/number values and deterministic repeat output, enforce a 512-byte ceiling without shortening a long identifier, reject out-of-range or missing budgets, omit private paths, token values, token-keyed counts and unsafe object-key paths, and deny cross-project retrieval. New cases cover required-pointer count, uniqueness and length; JSON Pointer syntax; exact retention against 400 competing eligible codes; generic unavailable errors for unsafe/missing fields; project scope; and a 512-byte all-required failure.

Limits: this slice parses the full stored payload locally before selecting facts; it can reduce returned context bytes but does not reduce database read or local parsing cost. Required pointers are caller-selected, not inferred from a task, and cannot elevate coordinates or other fields outside the conservative allowlist. This slice does not yet deduplicate across results, rank findings, protect all domain-specific exact fields, or measure model tokens. The deterministic Context Gauntlet fixture is recorded in `PHASE4_CONTEXT_GAUNTLET_FIRST_FIXTURE.md`; the broader model/client comparison remains open. A trusted client must still apply the project's data-egress policy before remote use.
